# БЛИК — запись на автомойку

Веб-приложение на **Vanilla JS (ES-модули) + Firebase Firestore + Firebase Authentication**.
Тема №26 из списка: **CarWash Booking — запись на автомойку**.
Вторая версия того же проекта: та же функциональность и схема БД, но более яркий,
многоцветный дизайн с анимациями появления (карточки, секции, модалки).

Каталог: услуги мойки → страница услуги с живыми слотами и отзывами → корзина записей →
личный кабинет с историей и своими машинами → админ-панель.

## 1. Структура проекта

```
carwash-booking/
├── index.html            # каталог услуг (поиск, фильтр, сортировка, пагинация, realtime)
├── service.html           # детальная страница услуги: бронирование, отзывы, похожие услуги
├── bookings.html          # «Мои записи» — активные действия (корзина/подтверждённые)
├── profile.html           # личный кабинет: профиль, машины, история, свои отзывы
├── admin.html             # админ-панель (только role === "admin")
├── css/style.css
├── js/
│   ├── firebase-config.js # инициализация Firebase — впишите сюда свои ключи
│   ├── ui.js               # общие хелперы (toast, форматирование, поиск ключевых слов)
│   ├── header.js           # общая шапка + модалка входа/регистрации, состояние авторизации
│   ├── catalog.js          # логика index.html
│   ├── service.js          # логика service.html
│   ├── booking.js          # логика bookings.html
│   ├── profile.js          # логика profile.html
│   ├── admin.js             # логика admin.html
│   └── reveal.js            # анимация появления секций при прокрутке
├── firestore.rules         # правила безопасности
└── firestore.indexes.json  # композитные индексы
```

Единственная точка, которую нужно отредактировать перед запуском — `js/firebase-config.js`.

## 2. Быстрый старт

1. Создайте проект на [console.firebase.google.com](https://console.firebase.google.com).
2. Включите **Authentication → Email/Password**.
3. Создайте базу **Firestore Database** (в тестовом режиме, затем примените `firestore.rules`).
4. В настройках проекта (⚙ → Project settings → Your apps → Web) создайте веб-приложение
   и скопируйте конфиг в `js/firebase-config.js`.
5. Разверните правила и индексы (нужен [Firebase CLI](https://firebase.google.com/docs/cli)):
   ```bash
   npm install -g firebase-tools
   firebase login
   firebase init firestore   # выберите существующий проект
   firebase deploy --only firestore:rules,firestore:indexes
   ```
   Индексы также можно не деплоить заранее — Firestore сам покажет в консоли ссылку
   «Create index» при первом запросе, которому не хватает индекса.
6. Откройте `index.html` через локальный сервер (модули `type="module"` не работают
   через `file://`):
   ```bash
   npx serve .
   # или: python3 -m http.server 5500
   ```
7. Опубликуйте на **GitHub Pages**: Settings → Pages → Deploy from branch → `main` / `root`.

## 3. Первый администратор

Регистрация всегда создаёт пользователя с ролью `user` (это защищено правилами безопасности —
роль `admin` нельзя присвоить себе через клиент). Чтобы получить первого админа:

1. Зарегистрируйтесь на сайте обычным способом.
2. В Firebase Console → Firestore → `users/{ваш uid}` вручную поменяйте поле `role` на `admin`.
3. Обновите страницу — в шапке появится пункт «Админ-панель».

Дальше новых админов можно назначать прямо из админ-панели (вкладка «Пользователи»).

## 4. Схема базы данных

| Коллекция   | Документ                  | Поля |
|-------------|----------------------------|------|
| `users`     | `{uid}`                    | `name, email, phone, role ('user'\|'admin'), createdAt` |
| `services`  | автоID (основные сущности) | `name, category, description, price, durationMin, active, rating, reviewsCount, keywords[], createdAt` |
| `cars`      | автоID                     | `ownerId, make, model, plate, year, color, createdAt` |
| `bookings`  | автоID (действия)          | `userId, serviceId, serviceName, price, carId, carLabel, date ('YYYY-MM-DD'), time ('HH:MM'), status, createdAt, updatedAt` |
| `reviews`   | автоID                     | `serviceId, userId, userName, rating (1-5), text, createdAt` |

`status` записи (bookings) проходит путь:

```
draft (в корзине) → confirmed (подтверждена) → in_progress (в работе) → done (история)
                                              ↘ cancelled (история)
```

`draft`/`confirmed`/`in_progress` — активные действия, отображаются на `bookings.html`.
`done`/`cancelled` — попадают в историю на `profile.html`.

**Денормализация для производительности** (пункт 5.2 ТЗ): в `bookings` дублируются
`serviceName` и `carLabel`, чтобы список записей строился без дополнительных чтений
`services`/`cars`. В `services` хранится агрегированный `rating`/`reviewsCount`,
обновляемый при каждом отзыве — детальная страница не пересчитывает рейтинг по всем отзывам.

**Поиск** реализован через массив `keywords` (нижний регистр, токенизация названия +
описания + категории) и запрос `where('keywords', 'array-contains', term)` — это
настоящий запрос к Firestore, а не фильтрация уже загруженного списка на клиенте.

**Оптимизация запросов**: статистика в админ-панели использует `getCountFromServer()` —
агрегирующий запрос, который не скачивает документы, только считает их на сервере.

## 5. Realtime (`onSnapshot`)

- `index.html` — каталог обновляется в реальном времени при добавлении/изменении услуг админом.
- `service.html` — доступность слотов на выбранную дату слушается в реальном времени
  (`bookings` по `serviceId + date`), поэтому если кто-то занял слот, кнопка сразу
  становится недоступной без перезагрузки.
- `bookings.html` и `profile.html` — статус записи обновляется мгновенно, когда админ
  меняет его в админ-панели.

## 6. Как критерии ТЗ закрыты в проекте

| Критерий | Где |
|---|---|
| Аутентификация | `header.js`: регистрация/вход/выход/сброс пароля, сессия сохраняется Firebase SDK |
| Каталог с пагинацией | `catalog.js`: `limit()` + кнопка «Показать ещё» |
| Система действий | `service.js` (создание брони) + `booking.js` (подтверждение/отмена) |
| Личный кабинет с историей | `profile.js`: вкладки «Профиль / Машины / История / Отзывы» |
| Схема БД | раздел 4 этого README |
| Правила безопасности | `firestore.rules` |
| Real-time | раздел 5 этого README |
| Админ-панель | `admin.html` + `admin.js`: CRUD услуг, статусы записей, роли, модерация отзывов, статистика |
| Оптимизация запросов | денормализация (см. выше) + `getCountFromServer` + `firestore.indexes.json` |
| Качество кода / архитектура | разделение по файлам: конфиг / UI-хелперы / шапка / логика на страницу |

## 7. Наполнение каталога тестовыми данными

Быстрее всего добавить 8-10 услуг прямо через **вкладку «Услуги» в admin.html** —
форма создаёт документ с уже готовым `keywords[]`. Примеры категорий и услуг для темы
«автомойка» уже зашиты в выпадающий список категорий на `index.html`/`admin.html`:
Мойка кузова, Химчистка салона, Полировка и защита, Шины и диски, Комплекс.


## Быстрый запуск
Для просмотра интерфейса можно открыть `index.html` напрямую. В архиве есть резервный интерфейс, поэтому страница не должна становиться пустой при ошибке Firebase/JavaScript.
Для полной авторизации, записей и админ-панели нужно заменить `REPLACE_ME` в `js/firebase-config.js` на данные своего Firebase-проекта и запускать сайт через локальный сервер (например, Live Server в VS Code).
